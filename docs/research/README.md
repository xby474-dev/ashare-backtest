# 研究代码与复现说明

本研究考察 ETF 的中期相对动量、长期自身趋势与短期回调信号，比较新增信号是否改善下一月收益预测，以及这些信息能否转化为扣除交易费用后的组合表现。预测检验与策略回测分别进行，结果按宽基、行业和风格组汇总。

**当前进度：** 仓库已有事件驱动回测基础引擎、动量与趋势策略示例、合成数据演示和审计工具。下文七个模块描述正式研究的职责划分，属于拟实现的研究代码结构；当前实际代码位于 [`ashare/`](../../ashare)，尚未建立这些 `src/*.py` 文件。一般及条件回调、嵌套预测回归、MSE 和 Rank IC 尚未实现，完整分组动态基金池规则仍需补充，真实市场实证结果尚未生成。逐项对应关系见[研究模块与现有实现](../REPRODUCIBILITY.md#研究模块与现有实现的对应关系)。

## 一、模块职责

拟定目录如下：

```text
src/
├── data_pipeline.py
├── universe.py
├── signals.py
├── regression.py
├── portfolio.py
├── backtest.py
└── evaluation.py
```

- **`data_pipeline.py`：数据处理。** 获取、清洗并对齐行情及分红、停牌、退市等事件数据，记录来源、提取日期和缺失处理。总回报序列用于信号计算，实际成交价格用于交易模拟。
- **`universe.py`：动态基金池。** 按各历史时点的上市状态、历史数据长度和流动性条件构建动态基金池，分别维护宽基、行业和风格组，保留退市产品真实存续期间的记录。
- **`signals.py`：研究信号。** 计算中期动量、长期趋势、一般短期回调和条件回调信号。信号仅使用月末当时可获得的信息，历史不足或波动率无法可靠估计时标记缺失。
- **`regression.py`：嵌套预测模型。** 在共同有效样本上估计嵌套预测模型，按扩展窗口生成下一月收益预测。比较新增信号前后的预测差异，保持样本与缺失处理口径一致。
- **`portfolio.py`：选券及配置。** 将信号转化为候选池、持仓名单及目标权重，实现选券、等权与逆波动率等配置。合格标的不足时按预定规则保留现金，不强行补足仓位。
- **`backtest.py`：成交、现金与费用。** 模拟下一可交易时点的成交，更新持仓和现金，计入现金分红、佣金与滑点；对停牌或无法成交情形按预定规则处理，并保存交易记录。
- **`evaluation.py`：预测与绩效评价。** 计算样本外 MSE、Rank IC，以及扣费收益、波动率、最大回撤、换手率等绩效指标，分别汇总各研究组和各策略版本的结果。

## 二、复现流程与记录

### 环境与数据

正式交付代码时，记录 Python 版本、依赖包版本及安装方式，保留原始数据快照、清洗后数据和提取日期。对数据缺口及异常记录保留处理说明，避免接口更新后结果无法对应。

真实数据还需明确交易日历、基金代码和分组口径、上市与退市日期、价格与成交量单位、分红及其他公司行动的核验范围。价格调整口径须与现金分红入账方式一致，避免重复计入收益。接入格式与核验要求见[数据指南](../DATA_GUIDE.md)。

### 参数与样本

统一记录信号窗口、强势阈值、持仓数量、费用假设及随机种子，固定训练、验证和最终测试区间。参数选择仅使用训练期与验证期信息，进入最终测试前冻结模型和交易规则。

研究配置还应明确调仓频率、信号与执行时点、分组方法、流动性门槛、缺失处理及现金保留规则。申请书中的窗口以月为口径；当前示例策略的窗口以有效行情观测数计，正式实现时需明确频率转换，不能直接套用相同数值。

### 运行顺序

先完成数据处理、动态基金池构建与信号计算，再分别进行嵌套预测检验和组合构建，随后执行回测并汇总评价指标。各版本使用一致的成交时点、成本假设和有效样本比较口径。

```text
数据快照 → 清洗与对齐 → 动态基金池 → 月末信号
                                      ├─ 嵌套预测模型 → 样本外 MSE、Rank IC
                                      └─ 选券及配置 → 成交与现金账本 → 扣费绩效
```

上图为正式研究的运行设计。现有命令运行的是回测基础引擎的合成演示，尚不包含完整预测检验分支。

### 结果留存

每次运行保存配置、运行日志和结果文件，包括逐期基金池、信号值、预测值、目标权重、成交记录、现金余额及评价结果。结果文件与本次数据版本和参数配置对应，便于追溯差异。

正式运行建议使用独立输出目录，记录代码标签、完整提交号、数据快照标识、配置及运行标识。当前报告导出到同一目录时会覆盖该目录内固定名称的报告文件，保留不同实验时应分别指定 `--output`。

## 三、基本核验

为确认程序实现与研究设计一致，将在正式回测和结果汇总前选取若干代表性月份和 ETF，人工核对信号日期、基金纳入条件、成交时间、分红、现金及费用，确认没有使用未来信息。复现后检查资金账目能否勾稽、缺失值处理是否一致，以及相同数据与配置下的核心输出是否一致。上述核验用于确认程序符合研究设计，不预设策略一定获得正收益或显著结果。

核验记录应覆盖以下几类情况：

| 情形 | 核对内容 |
|---|---|
| 月末生成信号、下一可交易时点执行 | 输入信息截止时间、预测收益区间和实际成交时间是否对应 |
| 新上市、退市及历史数据不足 | 基金是否只在真实存续期间进入候选范围，缺失是否按规则处理 |
| 停牌或无法成交、合格标的不足 | 拒单、持仓和剩余现金是否符合预定规则 |
| 分红与交易费用 | 权益与到账日期、现金变动及费用是否与账本勾稽 |
| 新增信号前后的预测比较 | 是否使用共同有效样本，测试期信息是否进入选参过程 |
| 相同输入重复运行 | 数据与配置是否一致，核心输出及差异记录是否可追溯 |

现有自动测试与审计工具的覆盖范围见[测试与验收说明](../VALIDATION.md)。软件测试通过不能替代真实数据核验或研究假设检验。

## 四、当前版本如何运行

仓库地址：[xby474-dev/ashare-backtest](https://github.com/xby474-dev/ashare-backtest)。申请书引用的固定代码版本为 **[v0.1.0](https://github.com/xby474-dev/ashare-backtest/releases/tag/v0.1.0)**，对应提交 [`fd67d45c819247d4f079a32456fec4667b09f9fb`](https://github.com/xby474-dev/ashare-backtest/commit/fd67d45c819247d4f079a32456fec4667b09f9fb)。本研究说明随 `main` 分支持续维护；复现代码时应检出固定标签，后续实现研究功能时另行发布新版本。

参考环境为 Python **3.12.14**、uv **0.12.19**。固定版本的环境文件：

| 环境文件 | 用途 |
|---|---|
| [`.python-version`](https://github.com/xby474-dev/ashare-backtest/blob/v0.1.0/.python-version) | 参考 Python 解释器版本 |
| [`pyproject.toml`](https://github.com/xby474-dev/ashare-backtest/blob/v0.1.0/pyproject.toml) | 包信息、构建配置及可选数据 SDK 依赖 |
| [`uv.lock`](https://github.com/xby474-dev/ashare-backtest/blob/v0.1.0/uv.lock) | 锁定依赖解析结果 |

安装 Git 和上述版本的 uv 后，依次执行：

```bash
git clone https://github.com/xby474-dev/ashare-backtest.git
cd ashare-backtest
git checkout --detach v0.1.0
uv sync --locked
uv run --no-sync python -m unittest discover -s tests -v
uv run --no-sync python -m ashare demo --research --output outputs/demo
uv run --no-sync python tools/verify_demo.py --replay
```

首次恢复环境可能需要联网下载解释器和构建工具。默认命令不启用可选行情 SDK；核心演示无需行情账户。完成后打开 `outputs/demo/index.html` 查看汇总报告。最后一条命令核对账本和输出文件哈希，并在同一环境下重跑演示检查输出是否一致。更详细的步骤见[固定版本复现指南](../REPRODUCIBILITY.md)。

**当前演示使用固定种子的合成价格与工作日历，不是真实 ETF 历史数据或交易所日历。** 演示结果用于验证程序流程，不能作为策略有效性的实证结论。

## 五、结果文件与问题反馈

当前每个回测运行目录保存以下主要文件；参数实验的完整记录位于 `outputs/demo/research_runs/<run_id>/`：

| 文件 | 内容 |
|---|---|
| `metadata.json`、`manifest.json` | 运行元信息及输出文件 SHA-256 清单 |
| `result.json`、`metrics.json` | 完整回测结果与绩效指标 |
| `equity.csv`、`positions.csv` | 净值、现金等逐期账户数据与持仓 |
| `signals.csv`、`orders.csv`、`fills.csv` | 目标持仓及信号与执行时点日志、订单与实际成交 |
| `ledger.csv` | 现金及持仓变动账本 |
| `holding_periods.csv`、`drawdowns.csv`、`report.html` | 持有区间、回撤及单次运行报告 |

以上为现有引擎输出。正式研究要求的逐期基金池、完整研究信号、预测值、MSE 与 Rank IC 等文件将在对应模块实现后补充；当前 `signals.csv` 不是逐 ETF 的完整因子面板。

数据快照和 `outputs/` 在本地留存，不随源码提交。真实数据的获取与共享须遵守来源的使用条件；行情账户密钥通过环境变量配置，不写入文档、配置示例或结果文件。

如复现失败，可在仓库 [Issues](https://github.com/xby474-dev/ashare-backtest/issues) 中提供代码版本、操作系统、Python 与 uv 版本、执行命令、去除密钥和个人信息后的报错，以及可复现问题的合成输入。涉及结果差异时附上数据快照标识和配置差异，便于区分数据变化、研究设定变化与程序问题。
