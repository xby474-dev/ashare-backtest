# 关键假设、数据口径与限制

## 价格与权益

1. 执行、持仓估值永远使用人民币未复权价格。复权价不可与现金分红重复计入。
2. `raw` 为有效原始收盘观测；`adjusted` 为 `close_t × factor_t / factor_asof`，归一锚点不越过信号日。缺因子报错，不补 1。
3. `total_return` 初始为 100，按完整的现金/拆分行动累乘 `(split_ratio × close_t + gross_cash_per_old_share) / raw_previous_close`。现金按除权日收盘再投，是分析指数。缺失/停牌行情不伪造观测，相关事件累计至下一个有效收盘处理。
4. 账户在除权日将现金分红确认为应收，资产净值包含应收；到 `pay_date` 才增加可交易现金。到账日在非交易日则在下个交易日事件中处理。该离散处理不为周末已到账分红额外精确补算利息。
5. `cash_dividend` 单位为每股**除权前股份**对应的税前人民币；`split_ratio` 为除权后/前股份总比率（送转 10% 则 1.1）。同一资产同一除权日的事件必须先合并。
6. `record_date` 的收盘持仓决定现金权益；未提供时使用除权前持仓。未填 `pay_date` 明确表示假设除权日到账。拆分直接变换除权日现持仓，保留原取得日；若存在红股延后上市、记录日与除权日间特殊权利转移，应扩展权益批次模型，不能以当前模型冒充。
7. 小数股在拆分后保留；不模拟零股现金补偿。只有整仓卖出可包含零股。纯浮点记账有 `1e-8` 数值容忍，不是券商逐分钱结算系统。
8. 公司行动完整性默认不成立，手工 bundle 和数据商 bundle 使用同一规则。必须通过 `actions_verified_metadata(...)` 或等价结构，明确声明核验资产、包含边界的日期范围和核验人；只有旧布尔标记 `corporate_actions_complete=True` 或显式 `actions=[]` 均不认证。证书是调用者声明，不是数据源完整性的自动证明；核验记录也随 metadata 进入输入指纹。
9. Engine 默认要求认证覆盖 bundle 全部资产的回测区间，以及推导缺失 `pre_close` 所用的更早有效原始收盘锚点。`total_return` 另要求覆盖资产首条有效历史观测至查询日，包含信号热身期，不能只认证 lookback。显式 `allow_incomplete_actions=True` 只适用于承认现金流可能缺失的价格研究，覆盖失败警告进入元数据；它不放行 total return，也不保证不完整行动下的账本和推导限价准确。

## 交易时序和成交近似

1. 所有信号在收盘后决策；执行只能在下一个显式交易日。月频指月末调仓，底层账本、公司行动、估值仍为日频。
2. 目标是**权重指令**，执行服务在选定开盘/收盘价下将权重转换为数量，并按执行时持仓净值定规模。这是理想化目标组合服务，假设能以该时点参考价确定规模；未模拟实际集合竞价报单截止前定量和截止后的不确定价格。若研究必须使用事前固定数量，应新增订单生成策略，不能把当前模型称为真实 MOO/MOC 队列。
3. 开盘成交不读取当日高、低、收盘或全天量；容量和冲击以最近一个更早 Bar 的量作为代理。它可能是停牌前旧量，不是可观察的当日集合竞价容量。没有历史量则拒单。收盘成交可使用当日量，但日量参与率也不是收盘竞价成交保证。
4. `suspended` 表示在开盘已知的整日停牌状态，不能事后用全天 volume=0 反推开盘可知停牌。行情缺失则当日不可交易；未来补发/修订须保留数据版本。
5. 官方 `limit_up/limit_down` 优先于规则比例。缺失时用交易所除权参考 `pre_close`；若也缺失，引擎使用最后一条非停牌原始 Bar 的收盘价，按时间顺序累计 `(该收盘日期, 执行日]` 的已生效现金分红和拆分推导参考。停牌 Bar 中的旧价不会重置锚点或漏掉除权行动。这一价格锚点独立于历史成交量查询，容量政策不变。无行动覆盖时限价推导仍不可靠。
6. 默认在涨停价不买、跌停价不卖，反向可以成交；不推断排队优先级。默认比例 10% 只是示例，必须用资产/日期覆盖描述 ST、不同板块、IPO、临时制度及 ETF 的差异。`limit_pct=None` 关闭推导限价，但已输入的官方限价仍有效。
7. 默认手数 100、T+1、股票 tick 0.01；ETF tick、T+0 资格及其他交易单位应逐标的设定。卖出资金同一交易日可再买，不模拟提现限制。
8. 目标未包含的持仓应卖至 0。先卖后买，同侧按 symbol 排序，卖不出时不能预支所得现金。现金不足会削减买量，不重新优化跨资产比例。因此买入顺序、整手、限价和停牌会造成可解释的跟踪误差。
9. 日订单只尝试一次：`filled` 全成，`partial` 部成且余量到期，`rejected` 不成并带原因；没有静默重试、跨日挂单或自动假成交。下个策略信号可重新发送权重。
10. 固定 bps 加线性参与率冲击作用于成交均价：`reference × [1 ± (bps + impact_bps × quantity / liquidity) / 10000]`，买用加号，卖用减号。参数非负，买价随数量单调上升、卖价随数量单调下降。均价允许落在 tick 之间；`slippage_cost` 用于审计，不再次从现金扣除。自定义滑点模型必须保留这种随数量单调恶化的性质，才能使用数量搜索。
11. `Broker(..., execution_mode="baseline")` 默认采用**缩量至边界**：候选数量的理论成交价若越界，就在合法整数手中二分搜索不越界的最大数量，并用该数量重新计算滑点价格。手数约束可能使最终价格略离边界；不通过经济意义上的截价保留过大的数量。若固定 bps 本身已越界或连一手也不可行，则拒单。仅吸收浮点运算舍入误差，理论价格恰好等于边界可成交。未越界的整仓零股卖出仍可成交；因边界缩量后遵循普通整手规则。
12. `execution_mode="optimistic"` 采用**边界价全额成交**：将理论价格截到涨跌停边界，保留全部候选数量。这是原逻辑的可选乐观假设。`execution_mode="conservative"` 采用**越界拒单**：候选数量的理论价格一旦越界就整笔拒绝，不再尝试用现金约束缩量使其可行。三种模式在未越界时使用同一成交逻辑，均保留原始参考价涨停不买、跌停不卖的方向锁定规则。若行情参考价与限价不一致（买入参考价低于跌停、卖出参考价高于涨停），baseline/conservative 以 `reference_outside_limits` 拒单；optimistic 保留旧截价行为。
13. 模式应用顺序为可卖数量/T+1、流动性容量、整手约束 → 涨跌停模式 → 买入现金约束。所谓 optimistic 的“全额”只指模式处理前的候选量，不豁免其他约束。baseline 因边界缩量后记录 `partial / price_limit`；无可行数量或 conservative 越界则记录 `rejected / price_limit`。之后现金约束若进一步缩量，则原因记为 `insufficient_cash`。费用、现金、持仓、成交额、滑点成本和已用容量均按实际成交数量记账；未成交余量当日到期。`execution_mode` 随 Broker 配置写入审计元数据并参与 `run_id`，应以相同输入比较三种假设的敏感性。这些模式都是日线研究近似，不模拟涨跌停队列中的真实成交概率。

规则例子（以下同样为研究假设）：

```python
from ashare.execution import TradingRules, FeeModel
rules = TradingRules(
    limit_pct=.10, max_participation=.05,
    asset_overrides={"ETF_A": {"limit_pct": .20}},
    date_overrides=[
        {"effective_date": "2023-01-01", "symbol": "NEW", "limit_pct": None},
        {"effective_date": "2023-01-09", "symbol": "NEW", "limit_pct": .20},
    ],
)
fees = FeeModel(stamp_tax_rate=.001,
                stamp_tax_schedule=[("2023-08-28", .0005)])
```

覆盖优先级为默认 → 资产覆盖 → 生效日期升序覆盖，同日期依输入顺序。历史费率应核验后输入，代码不从日期自动推断法规。

## 费用、现金和生命周期

- 默认交易成本：佣金万三、最低 5 元、股票卖出税 0.0005、过户费 0.00001。它们是可配置的研究参数；ETF/现金替代资产免上述股票卖税，但当前佣金/过户费参数对所有资产共用。精确到品种和券商可继承 FeeModel 重写 calculate。
- 不模拟个人所得税按持有期追补、配股认购、融资、融券、申赎篮子、基金管理费单独扣账。市场报价已体现的费用不能重复扣除。
- 现金利息以实际间隔自然日/365、配置的有效年利率累积，仅计入真实现金。默认 0。现金 ETF 是普通可交易资产，受到自身停牌、T+0/T+1、费用和容量约束，不承诺现金替代无风险。
- `list_date` 含当日，`delist_date` 定义为最后可交易日期且含当日。数据商行政退市日期未必等于该日期，需要外部核验；历史股票池应包含退市标的。
- 默认遇持仓退市后抛错，避免默认以最后价清仓。显式 `carry` 继续末价估值，`mark_zero` 将持仓估为 0 并保留份额；两者都会记警告，不创造清算所得。更精确的退市清算需添加专门现金流事件。
- 停牌/缺失行情默认保留旧估值，除权时相应调整旧价；每个受影响日期留 `stale_mark`。可选择 `missing_price_policy='error'`。

## 统计、实验与可复现性

- 始终从初始资金计算首个日收益；年化默认 252 个日观测，月频信号不改为年化 12。CAGR 这里按观测交易年数 `N/252` 计算，不按自然日期差。
- 波动率使用样本标准差；Sharpe 使用日均超额收益/日标准差×√252；Sortino 下行平方以全部日观测数为分母；未定义的比率是 JSON null。
- 最大回撤为负比例，峰值包括初始资金；另导出峰、谷、恢复日与未恢复区间。换手 `sum(abs(fill notional)/previous_equity)` 包含初次建仓；half_turnover 为其一半，不等于所有文献的单边轮动定义。
- 网格、消融本身是样本内研究，不能当样本外证明。walk_forward 每折只用训练绩效选参，冻结后测试，测试区间不得重叠；后折允许用已发生的前折测试区间重新训练。
- 输入指纹和不可变缓存能重放同一版本数据；不能恢复数据商未提供的历史修订版本，也不能自动消除幸存者偏差。历史指数成员、ST 标志、板块规则、财务公布时点等仍需逐时点数据输入。
- Python 的 HistoryView 是防误用接口，不是敌对代码安全沙箱；自定义策略可以自行联网或访问外部全量文件，这需要研究者自己禁止。测试证明内置路径的时点隔离，不证明任何自定义代码绝对不存在前视。

## 明确未实现

分钟/tick 撮合与竞价订单簿；订单排队和冲击校准；跨日有效限价单/撤改单；ETF 一级申赎；复合权证/配股/换股合并/现金替代交割；延迟上市红股可卖批次；自动历史规则数据库；券商级税款追补；多币种/杠杆/卖空；连续账户的无缝 walk-forward；分布式优化；全市场列式存储与向量化加速。

当前 SQLite 按内容存储完整规范化 JSON bundle，强调可审计性，适合日/月频中小股票池研究。全 A 股长期全集应增加按资产/日期分区的 Parquet 或数据库后端，同时保留 DataPortal 视图和指纹接口。
